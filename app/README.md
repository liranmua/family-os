# Family OS — שלב 1: Prototype PWA מקומי

אפליקציית שלד שרצה **לגמרי בצד הלקוח**. אין ענן, אין חשבונות גוגל, אין Firebase, אין
Push-שרת. כל הנתונים נשמרים ב-`IndexedDB` במכשיר של המשתמש בלבד.

מתפתח מ-`../family_hub_dashboard.html` (הסקיצה המאושרת) — ראו `../CLAUDE.md` ו-
`../Family_OS_Phase1_Handoff.md` להקשר מלא.

## הרצה מקומית

```
node scripts/serve.mjs 4173
```
ואז לפתוח http://localhost:4173 . (צריך שרת — `file://` לא ירשום Service Worker.)
שרת סטטי מינימלי, בלי תלויות npm.

## מה חי / מה עדיין לא

- **חי ומחובר** (נשמר ונטען מ-IndexedDB): כל ה-CRUD — משימות (כולל תתי-משימות), שגרות +
  סימון "בוצע היום", פרויקטים, רשימת קניות. KPIs. פילטר תחום. איפוס הכל.
- **חי אבל תלוי-הרשאה**: התראות מקומיות — עובדות רק אחרי שהמשתמש מאשר, ורק בזמן
  שהאפליקציה פתוחה או ברקע (בדפדפן שתומך ב-Notification Triggers גם אחרי סגירת הטאב).
  **אין** Push מהשרת.
- **מוקאפ בלבד / לא במימוש**: לוג העדכונים (`updatesLog`) מוצג אבל אין עדיין טופס להוספת
  רשומה. תצוגת פיננסים מופשטת — עדיין לא נבנתה (רק KPI כללי).

## בדיקה ידנית של התראות (לא ניתן לאוטומציה)

1. ללחוץ "אפשר התראות" בכותרת ולאשר בדפדפן.
2. להוסיף משימה עם תאריך = היום ושעה בעוד ~2 דקות.
3. להשאיר את הטאב פתוח. אחרי שהשעה מגיעה — אמורה להופיע התראת מערכת.
4. לרענן — ההתראה לא חוזרת (מפתח נשמר ב-`meta.notifiedIds`).
   לבדיקה מהירה: `window.__familyosNotifyTest()` ב-console.
